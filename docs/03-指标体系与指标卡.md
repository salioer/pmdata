# 03 指标体系与指标卡

## 一、体系结构

```
                    北极星：效率指数 E01
                           │
   ┌──────────────┬────────┴─────┬──────────────┬──────────────┐
 A 研发效率      B 人效         C AI 效能       D 数据质量      护栏
 E01–E07        P01–P05        A01–A08        Q01–Q03        G01–G02
```

**五个问题对应的总览指标（L1 一页纸）**

| 问题 | 总览指标 |
|---|---|
| 效率怎么样 | E01 效率指数 |
| AI 顶了多少 | A03 等效人力 |
| 人有没有被喂饱 | P01 人均吞吐当量（配合 P02 人均并发需求） |
| 数据能不能信 | Q01 V1–V8 达标率 |
| AI 的效率如何 | A05 ¥ / 当量 |
| 护栏 | G01 上线后 30 天缺陷数 / 当量 |

**进总览的规则**：必须能按"战场 × 规模档 × 周 / 月"下钻；不能下钻到战场的指标不进总览。

**结构化清单**见 [指标字典.csv](../metrics/指标字典.csv)，与本文一一对应。

## 三、指标卡

每张卡的字段：回答的问题、定义、公式、数据源、下钻、窗口、就绪与依赖、刷新、误读与作弊风险。

### E01 效率指数（北极星）

| 字段 | 内容 |
|---|---|
| 回答的问题 | 同样的人日，交付的活比 AI 推广前多了还是少了 |
| 定义 | 上线需求当量合计与名册可用人日合计之比 |
| 公式 | `E01 = Σ 上线需求当量 ÷ Σ 名册可用人日` |
| 数据源 | 当量：需求定档结果表 + 发布记录（上线月）；人日：HR / PMO 名册 |
| 下钻 | 战场 × 规模档 × 月（规模档下钻时分母按各档实际报工人日分摊，仅作诊断） |
| 窗口 | 滚动 3 个月；基线期 = 1.00 |
| 就绪与依赖 | 定档来源为大模型档时为结论级；TL 兜底档时为结论级但标"偏保守"；依赖 V5、V8 |
| 刷新 | 月度 |
| 误读风险 | ① 不同定档来源的战场不可直接比较；② 指数上升但 G01 恶化，属于"提速降质"；③ 指数包含流程改进、人员熟练等因素，不全是 AI 的贡献 |

### E02 吞吐当量

| 字段 | 内容 |
|---|---|
| 回答的问题 | 交付了多少活 |
| 公式 | `E02 = Σ 当期上线需求的需求当量` |
| 数据源 | 需求定档结果表、发布记录 |
| 下钻 | 战场 × 规模档 × 周 / 月 |
| 窗口 | 月度看趋势；结论用滚动 3 个月 |
| 误读风险 | 拆单不会增加当量（当量按规模算），这是用当量而不用需求数的原因 |

### E04 研发周期

| 字段 | 内容 |
|---|---|
| 回答的问题 | 一个需求从立项到上线要多久 |
| 定义 | 研发周期 = 上线日 − 立项日；开发周期 = 上线日 − 开发开始日（单位：工作日） |
| 公式 | 按上线月分组，取 P50 和 P85 |
| 数据源 | iSmart 里程碑；上线日以发布记录为准 |
| 下钻 | 战场 × 规模档 × 月 |
| 就绪与依赖 | V2 达标前为底数级 |
| 误读风险 | 必须分档看；档位结构变化会让整体周期失真 |

### E05 承诺兑现率

| 字段 | 内容 |
|---|---|
| 回答的问题 | 月初答应业务方的，交了多少 |
| 公式 | `当月兑现率 = 本月排期且本月上线数 ÷ 本月排期数`；M+1 / M+2 累计兑现率同理按排期月分批累计 |
| 数据源 | iSmart 月初排期冻结快照、发布记录 |
| 下钻 | 战场 × 排期月 |
| 误读风险 | 这是承诺口径，与产出口径的"当月上线数"不同，两者的差异见第 07 篇桥接表 |

### E06 计划膨胀率

| 字段 | 内容 |
|---|---|
| 公式 | `E06 = 本月移出数 ÷ 本月排期数`；辅以"实际周期 ÷ 计划周期"的分档中位数 |
| 数据源 | 排期冻结快照、里程碑计划与实际 |
| 误读风险 | 移出可能来自业务方调整，不全是研发原因；需结合移出原因看 |

### E07 分档单位人日（诊断）

| 字段 | 内容 |
|---|---|
| 公式 | `E07 = 某档上线需求的报工人日合计 ÷ 该档上线需求数` |
| 用途 | 只用于诊断某个档位的人日变化，不进总览 |
| 误读风险 | 依赖工时分配准确性，V1 / V3 不达标时不可信 |

### P01 人均吞吐当量

| 字段 | 内容 |
|---|---|
| 回答的问题 | 每个人每月交付多少活 |
| 公式 | `P01 = Σ 上线需求当量 ÷ 名册月均在册人数 ÷ 月数` |
| 数据源 | 需求定档结果表、名册 |
| 下钻 | 战场 × 资源类别（正式 / 数马）× 月 |
| 误读风险 | 与 E01 同源，人日按每月工作日折算后两者趋势一致；P01 的价值是可以按资源类别看 |

### P02 人均并发需求

| 字段 | 内容 |
|---|---|
| 回答的问题 | 每个人同时在做几个需求，AI 是否让人"喂饱"了更多需求 |
| 定义 | 一个人在一周内对某需求报过工，就算该人该周在做这个需求 |
| 公式 | `P02 = Σ（人 × 周 × 需求）组合数 ÷ Σ 在册人周` |
| 数据源 | 工时填报明细（个人级，仅用于聚合计算）、名册 |
| 下钻 | 战场 × 团队 × 周（不出个人） |
| 就绪与依赖 | V1、V3 达标前为底数级 |
| 误读风险 | 并发上升但吞吐不变、周期变长，说明是多线程空转而不是喂饱。必须用利特尔定律和 E02、E04 一起看（见第 05 篇） |

### P03 有效工时占比

| 字段 | 内容 |
|---|---|
| 公式 | `P03 = 挂到纳入吞吐的需求上的工时 ÷ 总报工工时` |
| 用途 | 看缺陷修复、运维、公共事务占用了多少产能 |

### P04 资源结构 / P05 填报饱和度

- **P04**：正式与数马的人数及占比，按战场 × 月。外包只在历史期单独列示。
- **P05**：`实填人日 ÷ 应填人日`，应填人日以名册在册工作日为准。是 V1 的配套指标。

### A03 AI 同期提效人日 / 等效人力

| 字段 | 内容 |
|---|---|
| 回答的问题 | AI 顶了多少人 |
| 公式 | `提效人日 = Σ 当量 − Σ 名册可用人日`；`等效人力 = 月均提效人日 ÷ 月工作日` |
| 下钻 | 战场 × 月（滚动 3 个月） |
| 对账 | 与同期数马人数的减少量对照 |
| 误读风险 | 归因措辞统一用"与 AI 推广同期的提效"，不说"全部由 AI 带来"；详见第 06 篇 |

### A05 ¥ / 当量

| 字段 | 内容 |
|---|---|
| 回答的问题 | 每交付一个当量花了多少 AI 费用 |
| 公式 | `A05 = Σ AI 费用 ÷ Σ 上线需求当量` |
| 数据源 | Token 消耗明细（P1 标准化后）、需求定档结果表 |
| 就绪与依赖 | Token 明细标准化前为"不出" |

### Q01 V1–V8 达标率

| 字段 | 内容 |
|---|---|
| 回答的问题 | 数据能不能信 |
| 公式 | 每条规则按红黄绿判定；`Q01 = 绿灯规则数 ÷ 规则总数`，并列出红灯规则 |
| 下钻 | 战场 × 规则 × 周 |
| 用途 | 决定其他指标的就绪等级（见第 04 篇的解锁关系） |

### G01 上线后 30 天缺陷数 / 当量

| 字段 | 内容 |
|---|---|
| 回答的问题 | 提速有没有以牺牲质量为代价 |
| 公式 | `G01 = 上线后 30 天内关联到该批需求的生产缺陷数 ÷ 该批需求当量` |
| 数据源 | 线上质量数据（P0 补建：最小集为上线后 30 天缺陷数） |
| 规则 | G01 相对基线恶化超过阈值时，该战场的 E01 在总览上标黄，不论 E01 多高 |

其余指标（A01、A02、A04、A06–A08、Q02、Q03、G02）的定义见第 06 篇、第 02 篇和指标字典。
