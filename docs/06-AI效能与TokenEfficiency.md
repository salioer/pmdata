# 06 AI 效能与 Token Efficiency

AI 效能回答两个问题：**AI 顶了多少**，以及 **AI 花得值不值**。按四层来看：

| 层 | 问题 | 指标 | 当前就绪等级 |
|---|---|---|---|
| 采用层 | 用起来了没有 | A01 覆盖率、A02 会话挂接率 | 底数级 |
| 产出层 | 产出了什么 | AI 代码行占比（仅辅助）、A08 采纳率 / 留存率 | A08 不出（需补建埋点） |
| 结果层 | 顶了多少 | A03 提效人日 / 等效人力、A04 对照 | A03 结论级，A04 只作佐证 |
| 成本层 | 花得值不值 | A05 ¥ / 当量、A06 ¥ / 提效人日与 ROI、A07 无效会话占比 | A05 / A06 不出，Token 明细标准化后升级 |

---

## 一、采用层

| 指标 | 公式 | 数据源 |
|---|---|---|
| A01 AI 覆盖率 | 有 AI 工具遥测记录的人 ÷ 在册研发人员 | AI 工具遥测、名册 |
| A02 会话挂接率 | 能关联到需求 ID 的会话 ÷ 总会话 | AI 工具遥测 |

两者同时也是 V7.1、V7.2 的校验指标。覆盖率低时，后面所有 AI 指标都只能出底数。

---

## 二、产出层

- **AI 代码行占比**：AI 工具遥测里的代码行数据只作辅助证据，不进总览。代码行会被 AI 放大，不能代表产出。
- **A08 采纳率 / 留存率**：AI 生成的代码有多少被采纳、上线后留存多久。这是返工率的唯一来源，需要补建采纳埋点（P1），补建前不出。

---

## 三、结果层：AI 顶了多少

### 3.1 主口径：缺口法

```
AI 同期提效人日 = Σ 需求当量 − Σ 名册可用人日
等效人力       = 月均提效人日 ÷ 月工作日
```

含义：按 AI 推广前的效率，交付这些当量需要多少人日；实际只用了多少人日；差额就是同期提效的部分。

**算例（虚拟战场 A，滚动 3 个月）**：当量 1,200，名册可用人日 1,008，提效人日 192，等效人力 ≈ 3.0 人。同期数马减少 4 人，即 AI 同期顶上了约 3 人，缺口约 1 人。

**与数马减少量对账**

| 情况 | 解读 |
|---|---|
| 等效人力 ≥ 数马减少人数 | 提效覆盖了减员，交付量不降反升 |
| 等效人力 < 数马减少人数 | 提效部分覆盖减员，交付量有所下降 |
| 等效人力 ≤ 0 | 没有看到提效，需要排查（先看定档来源是否为偏保守的 TL 档） |

### 3.2 辅助口径：对照法（A04）

同战场、同档位内，比较"有 AI 会话挂接的需求"和"没有挂接的需求"的单位人日。

- **只作佐证**：用不用 AI 不是随机分配的，存在选择偏差（例如简单需求更容易用 AI）。
- 依赖 V7.2 会话挂接率和 V3 工时挂接准确性。

### 3.3 归因要克制

缺口法算出的提效，混有流程改进、人员熟练、需求结构变化等因素。

- 统一表述为**"与 AI 推广同期的提效"**，不说"全部由 AI 带来"。
- 当缺口法和对照法方向一致时，可以说"有证据表明 AI 是提效的主要因素之一"。

## 四、成本层：Token Efficiency

### 4.1 指标

| 指标 | 公式 | 含义 |
|---|---|---|
| A05 ¥ / 当量 | Σ AI 费用 ÷ Σ 上线需求当量 | 每交付一个当量花多少 AI 费用 |
| A06 ¥ / 提效人日 | Σ AI 费用 ÷ 提效人日 | 每省一个人日花多少 AI 费用 |
| A06 ROI | （提效人日 × 数马人日单价 − AI 费用）÷ AI 费用 | 和用数马相比，AI 的投入产出比 |
| A07 无效会话占比 | 没有产出执行计划或代码、也没有挂接需求的会话 ÷ 总会话 | Token 有没有浪费在无效对话上 |

### 4.2 算例（虚拟战场 A，滚动 3 个月）

| 项目 | 数值 |
|---|---|
| AI 费用 | ¥60,000 |
| 需求当量 | 1,200 |
| 提效人日 | 192 |
| 数马人日单价（假设） | ¥1,500 |
| A05 ¥ / 当量 | 60,000 ÷ 1,200 = **¥50** |
| A06 ¥ / 提效人日 | 60,000 ÷ 192 = **¥312.5** |
| A06 ROI | （192 × 1,500 − 60,000）÷ 60,000 = **3.8 倍** |

> 数马人日单价为假设值，正式计算时按 PMO 提供的实际单价替换。

### 4.3 怎么读

- **A05 趋势下降**：同样的活花的 Token 更少，AI 使用越来越高效。
- **A06 ¥ / 提效人日远低于数马人日单价**：用 AI 替代人力在经济上划算。
- **A07 偏高**：Token 被浪费在无效会话上，需要做工具培训或优化使用方式。
- **只看 Token 总量没有意义**：Token 用得多可能是用得深，必须和产出（当量）放在一起看。

## 五、数据前提：Token 消耗明细标准化（P1）

目前 Token 消耗没有统一明细，A05 / A06 只能"不出"。P1 需要补建以下字段：

| 字段 | 说明 |
|---|---|
| 会话 ID | 唯一标识 |
| 时间 | 会话开始和结束时间 |
| 人员标识 | 哈希脱敏后的 ID，仅用于聚合到团队 |
| 战场、团队 | 由人员标识关联名册得到 |
| AI 工具 | 工具名称和版本 |
| 模型 | 模型名称和版本 |
| 输入 / 输出 / 缓存 Token 数 | 分别记录 |
| 费用 | 按模型单价计算 |
| 关联需求 ID | 可为空；为空的计入挂接率分母 |
| 产出标记 | 是否产出执行计划、是否产出代码 |

**补建完成后的升级条件**：V7.3 Token 明细完整率达到绿灯，A05 / A06 升为结论级。

---

## 六、隐私与红线

- **不读会话原文**：只取会话的统计特征（时长、轮次、Token、是否有产出）。
- **不到个人**：所有 AI 指标最细到"战场 × 团队 × 周"。
- **不进 KPI**：AI 使用数据不用于个人绩效评价，避免"为了用而用"刷数据。
