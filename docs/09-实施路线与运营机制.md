# 09 实施路线与运营机制

## 一、分阶段计划

### P0 摸底与止血（约 2–4 周）

| 工作项 | 产出 | 验收标准 |
|---|---|---|
| 跑 V1–V8 底数 | 数据质量基线报告（分战场） | 每条规则都有底数，阈值按实际分布校准一次 |
| 字段级权威源表、antom 状态映射表 | 两张表定稿 | 相关系统负责人确认 |
| antom 同步对账 | 漏单清单、冲突清单；近 12 个月存量清理 | V8.1、V8.2 有底数，存量异常有处理计划 |
| iSmart 月初排期冻结快照 | iSmart 需求提交并排期上线 | 首次冻结成功 |
| 线上质量数据最小集 | 上线后 30 天缺陷数的采集方案 | 能按需求关联缺陷 |
| 统计 PR 挂接率 | 分战场 PR 挂接率 | 判断各战场核验样本是否够用 |
| 测文档充分率 | 用大模型抽样跑一批需求 | 分战场文档充分率底数 |
| 盘点知识库现状 | 各战场应用目录、接口目录、已有文档的现状 | 为 P2 选试点战场提供依据 |
| 存量看板盘点 | 盘点表 | 每个看板都有四象限归类 |
| 确认基线期 | 基线期起止月份 | 写入第 01 篇 |

### P1 首版账本（约 4–6 周）

| 工作项 | 产出 | 验收标准 |
|---|---|---|
| 效率指数 v1 | 名册分母 + TL 兜底档，按战场出 E01、A03 | 标注"偏保守"；基线期 = 1.00 |
| 双口径与桥接表 | 各战场月度桥接表、承诺口径分批跟踪表 | 存量方程平衡；① + ② + ③ = 当月上线 |
| 数据质量看板 | V1–V8 红黄绿、异常清单 | 每周自动运行 |
| L1 一页纸、L2 战场页 v1 | 首期月报 | 所有指标标注就绪等级 |
| 旧指标首批下线 | 按盘点结果下线"下线"象限的指标 | 使用方已通知 |
| Token 明细标准化方案 | 字段标准与采集方案（见第 06 篇） | AI 工具方确认 |

### P2 知识库与定档试点

按第 02 篇的试点流程（约 11 周 + 2–3 个月双轨），在选定的试点战场完成：

| 工作项 | 产出 | 验收标准 |
|---|---|---|
| 知识库冷启动 | 试点战场知识库 v1 | 应用目录覆盖率 ≥ 90% |
| 尺子 v1 定版 | 模型版本、提示词、知识库快照 | 重跑一致率 ≥ 95% |
| 基线校准 | 权重表、切档点、k 值 | 基线期效率指数 = 1.00 |
| 双轨运行 | 双轨报告、档位一致性矩阵 | 召回率 ≥ 70%，文档充分率 ≥ 60% |
| 切换 | 试点战场切换到大模型档 | PM 团队验收通过 |
| 质量护栏上线 | G01、G02 | 能按战场出数 |

### P3 推广与 AI 账本

| 工作项 | 产出 | 验收标准 |
|---|---|---|
| 其余战场逐个切换 | 各战场知识库与定档 | 每个战场达到就绪标准后切换 |
| Token 明细上线 | 标准化 Token 明细 | V7.3 绿灯；A05、A06 升为结论级 |
| 采纳埋点 | AI 产出采纳 / 留存数据 | A08 出数 |
| 业务需求池、环境等待、业务验收（P2 优先级数据） | 供需前瞻、异常归因 | 按需推进 |

## 三、角色分工

| 角色 | 职责 | 新增负担 |
|---|---|---|
| PM 团队 | 体系负责人：口径与指标字典、月报、知识库标准与验收、变更评审 | 体系运营 |
| 数据团队 | 数据接入、V 规则运行、大模型定档运行、看板开发 | 开发与运维 |

| 战场接口人 | 接收异常清单、推动修复 | 异常处理 |

| 研发人员 | **沿用现有动作**：报工 | 无 |
| HR / PMO | 按月提供名册 | 无（已有月表） |

## 四、运营节奏

| 频率 | 动作 | 参与方 |
|---|---|---|
| 每日 | antom 对账；同步失败告警 | 数据团队（自动） |
| 每周 | V1–V8 运行；异常清单推送到各战场接口人 | 数据团队、战场接口人 |
| 每月 | 第 3 个工作日排期冻结；月报（L1 + L2）发布；月度经营复盘 | PM 团队、各战场负责人 |
| 每季度 | 知识库快照版本发布；定档核验报告（召回率、稳定性）；红黄绿阈值与指标评审 | PM 团队、架构师、数据团队 |
| 每年 | 定档权重复核；基线期与 k 值复核 | PM 团队、数据团队 |

## 五、风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 知识库建设进度慢 | 迟迟无法切换到大模型档 | 借 AI 转型推动（知识库同样服务于 AI 研发工具）；未切换期间 TL 兜底档照常出数并标"偏保守" |
| 需求文档质量长期偏低 | 文档充分率不达标 | 按战场公示文档充分率；不达标的战场继续 TL 兜底 |
| PR 挂接样本过少 | 无法核验大模型定档 | 用重复测量和战场级总量交叉验证补充；样本过少的战场单点推动挂接 |
| 大模型版本升级 | 尺子变化，前后不可比 | 按换尺子流程用重叠期接续 |
| 效率指数被误读为"AI 全部贡献" | 结论失真 | 统一归因措辞；同时展示对照法结果 |
| 指标被用于个人考核 | 数据失真、填报抵触 | 红线写入方案；看板不出个人数据 |
| 新旧两套数并存 | 口径打架 | 新指标上线即下线旧指标；指标字典作为唯一口径源 |
