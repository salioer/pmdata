# 05 效率与人效衡量方法

## 一、底层原理：工时守恒

**一个人一周最多填 5 天。** 所以无论 AI 用得多好，工时填报总量近似守恒：

```
总报工人日 ≈ 在册人数 × 工作日
```

这意味着：
- AI 的提效**不会**体现为"总工时变少"。
- AI 的提效体现为**"同一份工时喂饱了更多需求"**。

**三条要看的曲线**

| 曲线 | 期望方向 | 对应指标 |
|---|---|---|
| 单位需求人日（分档） | ↓ | E07（诊断） |
| 人均并发需求 | ↑（要配合吞吐和周期看） | P02 |
| 同等人力的吞吐当量 | ↑ | E01、E02、P01 |

**推论：北极星只用工时总量。** 总量可信（受名册约束），不可信的是工时分配到了哪个需求。所以北极星的分母用名册可用人日，不用"挂到需求上的工时"；工时明细只作诊断。

## 二、北极星：效率指数

```
效率指数 = Σ 上线需求当量 ÷ Σ 名册可用人日
```

| 组成 | 口径 | 为什么这样取 |
|---|---|---|
| 分子：需求当量 | 大模型定档的要素分 × k（知识库未就绪时用 TL 兜底档） | 按"要做什么"计量，不随人日漂移，拆单也不会虚增 |
| 分母：名册可用人日 | Σ 每人每月在册工作日，按人的所属战场归集 | 来自 HR / PMO 名册，不依赖工时分配的准确性 |
| 窗口 | 滚动 3 个月 | 抹平跨月需求造成的边界效应 |
| 基准 | 基线期 = 1.00 | 由 k 值保证 |

### 2.1 算例（虚拟战场 A）

**基线期**（AI 推广前 6 个月）

| 项目 | 数值 |
|---|---|
| 在册人数 | 20 人 |
| 名册可用人日 | 20 × 21 × 6 = 2,520 |
| 上线需求要素分合计 | 3,150 |
| k 值 | 2,520 ÷ 3,150 = 0.8 |
| 需求当量合计 | 3,150 × 0.8 = 2,520 |
| 效率指数 | 2,520 ÷ 2,520 = **1.00** |

**当期**（滚动 3 个月；数马减少 4 人）

| 项目 | 数值 |
|---|---|
| 在册人数 | 16 人 |
| 名册可用人日 | 16 × 21 × 3 = 1,008 |
| 上线需求要素分合计 | 1,500 |
| 需求当量合计 | 1,500 × 0.8 = 1,200 |
| 效率指数 | 1,200 ÷ 1,008 = **1.19** |
| AI 同期提效人日 | 1,200 − 1,008 = 192（3 个月） |
| 等效人力 | 192 ÷ 3 ÷ 21 ≈ **3.0 人** |

**怎么读**：人少了 4 个（−20%），月均交付当量从 420 降到 400（−5%）。效率提升约 19%，相当于 AI 同期顶了约 3 个人；剩下约 1 个人的缺口，体现为交付量的小幅下降。

### 2.2 为什么不用"单位需求人日"做北极星

| 问题 | 单位需求人日 | 效率指数 |
|---|---|---|
| 依赖工时分配准确性 | 是（V1 / V3 不达标就不可信） | 否 |
| 受档位结构影响 | 是，必须分档看 | 否，当量已按规模加权 |
| 受拆单影响 | 是 | 否 |

单位需求人日保留为 E07，用于诊断"哪个档位的人日在变化"。

## 三、人效

### 3.1 人均吞吐当量（P01）

```
P01 = Σ 上线需求当量 ÷ 名册月均在册人数 ÷ 月数
```

**算例**：战场 A 基线期 2,520 ÷ 20 ÷ 6 = 21 当量 / 人·月；当期 1,200 ÷ 16 ÷ 3 = 25 当量 / 人·月，提升约 19%，与效率指数一致。

P01 与 E01 同源，它的额外价值是**可以按资源类别（正式 / 数马）拆开看**。

### 3.2 人均并发需求（P02）与利特尔定律

```
P02 = Σ（人 × 周 × 需求）组合数 ÷ Σ 在册人周
```

一个人一周内对某需求报过工，就算这个人这周在做这个需求。

**并发上升不一定是好事。** 如果并发上升但吞吐没涨、周期变长，说明是多线程空转，而不是被"喂饱"。所以 P02 必须和吞吐、周期一起看，用**利特尔定律**做一致性校验：

```
开发中在制数 ≈ 日吞吐 × 平均周期（工作日）
```

**算例**：战场 A 当月上线 44 个需求，日吞吐 ≈ 44 ÷ 21 ≈ 2.1 个；开发中在制平均 25 个，推算平均周期 ≈ 25 ÷ 2.1 ≈ 12 个工作日。
- 如果 iSmart 里程碑算出的周期 P50 也在 12 天左右，数据自洽。
- 如果里程碑周期是 20 天，三者对不上，说明里程碑不准（查 V2）或在制状态没有及时更新（查 V6.1）。

**解读规则**

| P02 | E02 吞吐 | E04 周期 | 判断 |
|---|---|---|---|
| ↑ | ↑ | 持平或 ↓ | 被喂饱了，健康 |
| ↑ | 持平 | ↑ | 多线程空转，需要控制在制 |
| 持平 | ↑ | ↓ | 单需求做得更快，健康 |
| ↓ | ↓ | — | 需求供给不足，查业务需求池 |

### 3.3 有效工时占比（P03）

```
P03 = 挂到纳入吞吐的需求上的工时 ÷ 总报工工时
```

看缺陷修复、运维、公共事务占用了多少产能。P03 下降而 E01 持平，说明研发在需求上的效率其实提高了，只是被非需求工作吃掉了一部分。

### 3.4 资源结构（P04）

- 正式与数马的人数和占比，按战场 × 月。
- 外包本月裁撤完毕，只在历史期单独列示；基线期的外包人日计入基线期名册可用人日。
- 数马人数的变化与 A03 等效人力对照，回答"AI 顶上的部分是否覆盖了数马的减少"。

## 四、研发效率的辅助指标

| 指标 | 用途 | 注意 |
|---|---|---|
| E04 研发周期 P50 / P85 | 看交付速度 | 必须分档看；V2 达标前只出底数 |
| E05 承诺兑现率 | 看对业务方的承诺兑现 | 承诺口径，和产出口径的差见第 07 篇 |
| E06 计划膨胀率 | 看排期稳定性 | 要结合移出原因 |
| E07 分档单位人日 | 诊断某档人日变化 | 依赖 V1 / V3 |

## 五、总体解读规则

1. **先看门禁，再看数。** 指标是底数级时，只描述现象，不下结论。
2. **先看护栏。** G01 恶化超过阈值时，不论效率指数多高，该战场总览标黄。
3. **看定档来源。** TL 兜底档的战场效率偏保守，不能和大模型档的战场直接比高低。
4. **看趋势，不看单月。** 结论用滚动 3 个月，单月只看方向。
5. **归因要克制。** 效率指数的变化包含 AI、流程改进、人员熟练等多种因素，统一表述为"与 AI 推广同期的提效"。
